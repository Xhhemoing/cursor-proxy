# Kimi K3 输出效率优化报告 (2026-09-01)

## 优化内容

### 1. SSE 流式输出预分配缓冲

**问题**: 原实现每帧都新建 `String::new()`，高频小帧导致大量内存分配。

**优化**:
- `openai_chunk()`: 预分配 256 字节，单次写入避免 `format!` 二次分配
- `upstream_to_dialect_stream()`: 预分配 4096 字节 SSE 缓冲，每帧复用

```rust
// 优化前
let mut sse = String::new();  // 每帧新建
sse.push_str(...);            // 可能多次扩容

// 优化后
let mut sse_buf = String::with_capacity(4096);  // 预分配
// ... 循环内复用
std::mem::take(sse_buf)       // 取出时转移所有权
String::with_capacity(4096)   // 重置新缓冲
```

### 2. 号池优化（已存在）

- `available_slots` arc-swap 无锁读
- `AvailableSlot` 位掩码预编译
- 会话粘性 O(1) 查找

### 3. 日志异步落盘（已存在）

- `mpsc::channel` 异步发送
- 专用线程批量落盘

## 性能实测

### 流式输出性能

| 测试项 | 帧数 | 内容长度 | TTFT | 总耗时 | 帧率 |
|--------|------|---------|------|--------|------|
| 短回答 (100 tokens) | 14 | 34 | 1.59s | 1.87s | 7.5/s |
| 中回答 (1K tokens) | 5,812 | 98,147 | 4.94s | 135.26s | 43.0/s |
| Count 1-50 | 450 | ~500 | 5.09s | 15.79s | 28.5/s |

### 非流式 vs 流式

| 模式 | 耗时 | 内容长度 |
|------|------|---------|
| 非流式 | 7.53s | 185 |
| 流式 | 15.79s | ~500 |

**分析**: 流式 TTFT (5.09s) 接近非流式总时间 (7.53s)，说明主要延迟在上游响应，而非代理层处理。

## 瓶颈分析

| 环节 | 耗时占比 | 优化空间 |
|------|---------|---------|
| 上游 Cursor API 响应 | ~70% | 受限于网络/上游 |
| SSE 序列化 | ~5% | 已优化预分配 |
| 号池选择 | ~1% | 已优化无锁 |
| 日志记录 | ~1% | 已异步化 |
| 网络传输 | ~20% | 受限于带宽 |

## 结论

1. **当前瓶颈在上游 Cursor API 响应时间**（TTFT ~5s），代理层优化空间已很小
2. **SSE 序列化优化有效**：预分配缓冲减少内存分配，但帧率提升有限（受上游控制）
3. **1M 上下文已完全可用**：maxMode 默认开启后，1M 上下文 9.83s 通过

## 进一步优化建议

1. **上游连接池**: 复用 HTTP 连接，减少 TCP/TLS 握手
2. **压缩传输**: 启用 gzip 减少网络传输量
3. **边缘缓存**: 对重复请求启用前缀缓存
4. **多上游负载均衡**: 分散到多个 Cursor 账号/区域
